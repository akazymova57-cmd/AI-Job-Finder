# AI Job Finder

Статический сайт для поиска международной удалённой работы. Интерфейс работает на HTML, CSS и vanilla JavaScript; сборщик и npm-пакеты для запуска не требуются.

## Возможности текущей версии

- Поиск и фильтрация вакансий из нескольких источников: Remote OK, Jobicy, We Work Remotely и Himalayas.
- Сопоставление текста вакансии с резюме по прозрачному словарю ключевых навыков.
- Избранное и трекер откликов в localStorage браузера.
- Проверка ссылок: только HTTPS и домены, явно перечисленные в `config.js`.
- Фильтр вакансий старше 30 дней и записей без названия компании.
- Базовые эвристики для выявления подозрительных формулировок.
- Переключатель RU/EN, сохранение выбранного языка.
- Кнопка перевода описания вакансии через публичный MyMemory API.
- Жалоба на вакансию открывает форму создания GitHub Issue.
- Адаптивный интерфейс с отдельной колонкой фильтров на широком экране.

## Запуск локально

Откройте `index.html` в браузере. Если браузер блокирует сетевые запросы при открытии файла напрямую, запустите статический сервер:

```bash
python -m http.server 8000
```

Затем откройте http://localhost:8000.

## Источники вакансий и конфигурация

Список источников, разрешённые домены, максимальный возраст вакансии и шаблоны подозрительных фраз находятся в `config.js`.

Подключённые источники:

- **We Work Remotely** — публичный RSS-фид. Используем только опубликованные поля, показываем источник и ссылку на оригинальную вакансию. Географическое поле из RSS сохраняется отдельно, поэтому объявления вроде «USA Only» не попадают в Worldwide.
- **Himalayas** — публичный JSON API. Условия разрешают показывать вакансии на собственном сайте при видимой атрибуции и переходе по applicationLink. Не передаём эти объявления другим агрегаторам. Загружаем до 200 последних записей за один запуск; API обновляется примерно раз в сутки.
- **Remote OK** — публичный JSON API `https://remoteok.com/api`. Для использования обязательны ссылка на исходную вакансию и указание Remote OK как источника; логотип Remote OK без разрешения не используется.
- **Jobicy** — публичный JSON API `https://jobicy.com/api/jobs`. Условия API разрешают агрегаторы и коммерческие продукты при сохранении атрибуции и перехода к исходной карточке Jobicy.
- **Remotive** — временно отключён для новых загрузок до письменного подтверждения права на публичное отображение вакансий в агрегаторе. Старые записи без `source_id` могут оставаться в снимке только на переходный период и удаляются после успешного обновления.

Для We Work Remotely используется именно публичный RSS-фид, а не Jobs API: площадка прямо разрешает его использование при указании источника и ссылок на оригинальные вакансии. Indeed не подключён: публичное копирование и повторное распространение его данных без разрешения не допускается. Условия каждого нового источника проверяются до интеграции.

Каждый адаптер приводит данные к общей структуре: `title`, `company_name`, `url`, `publication_date`, `description`, `salary`, `job_type`, `tags`, `candidate_required_location`, `source_id` и `source_name`. Ссылки на вакансии проходят отдельную HTTPS-проверку по allowlist конкретного источника.

## Автоматическое обновление

Workflow `.github/workflows/refresh-jobs.yml` запускается каждые 6 часов и вручную через GitHub Actions. После получения данных `scripts/validate-jobs.mjs` проверяет названия, компании, даты, HTTPS-домены, дубликаты и подозрительные формулировки. Скрипт `scripts/update-jobs.mjs` получает данные Remote OK, Jobicy, We Work Remotely и Himalayas, нормализует их, отбрасывает старые, дублирующиеся и подозрительные записи, проверяет HTTPS/домен и сохраняет единый снимок в `data/jobs.json`. Для Jobicy обрабатывается постраничная выдача (до 500 записей за один запуск). Если один источник временно недоступен, его ещё актуальные предыдущие записи сохраняются; если недоступны все источники, снимок не перезаписывается. Сайт читает только опубликованный снимок и не обращается к API площадок напрямую.

Для работы workflow после слияния PR в `main` в Settings → Actions → General должно быть разрешено GitHub Actions с правом записи содержимого репозитория (workflow использует встроенный `GITHUB_TOKEN`; отдельный API-ключ не нужен).

## Ограничения безопасности и актуальности

- Возраст вакансии рассчитывается по дате публикации, которую возвращает источник. Вакансии без корректной даты скрываются.
- Проверка мошенничества эвристическая и не гарантирует обнаружение всех схем. Она может давать ложные срабатывания.
- Уровень английского в карточке извлекается по ключевым словам из текста вакансии; если явного уровня нет, показывается «не указан». Это не подтверждённая оценка работодателя.
- Проверка HTTPS и домена подтверждает только соответствие URL белому списку, но не гарантирует добросовестность работодателя.
- Кнопка жалобы создаёт черновик GitHub Issue; отправка зависит от действий пользователя и прав доступа к репозиторию.
- Перевод использует сторонний публичный сервис MyMemory и может быть ограничен по длине или частоте запросов.
- В текущей статической версии нет фонового мониторинга закрытых вакансий и серверного обновления. Для этого требуется GitHub Actions или backend. Автоматическое обновление данных выполняется GitHub Actions; браузер использует опубликованный снимок и локальный кэш.

## Резюме и приватность

Текст резюме анализируется в браузере и не отправляется в API вакансий. Сейчас поддерживаются TXT и MD. PDF/DOCX не разбираются.

## Ключи и переменные окружения

Для текущей клиентской версии API-ключи не нужны. Не помещайте секреты в JavaScript или GitHub Pages: все файлы фронтенда доступны посетителям. Если позднее будет добавлен backend или workflow с секретами, храните их в GitHub Actions Secrets / переменных окружения и документируйте имена в `.env.example`. Сам файл `.env` в репозиторий добавлять нельзя.

## Публикация

GitHub Pages может публиковать статический сайт из корня ветки, выбранной в настройках Pages. Для этой задачи изменения готовятся в отдельной ветке и попадут в основную только после проверки и слияния Pull Request.
